# IPv4 TCP implementation

The wire codec, sender policies and bounded connection engine are implemented under `kernel/net/tcp/`, with public interfaces under `kernel/include/net/tcp/`, tracked by [#118](https://github.com/frankischilling/Axiom64/issues/118). The Linux AF_INET/SOCK_STREAM adapter adds ordinary active/passive connections and native host interoperability in [#120](https://github.com/frankischilling/Axiom64/issues/120). Retained MSG_WAITALL progress and compact TIME-WAIT storage are implemented in [#123](https://github.com/frankischilling/Axiom64/issues/123). Full retained-call, reclamation and controlled NIC fault acceptance remain required in [#121](https://github.com/frankischilling/Axiom64/issues/121) and the complete transport checklist in [#109](https://github.com/frankischilling/Axiom64/issues/109). This integration does not complete the transport or VM operating-system milestones.

## Linux socket integration

`socket.cpp` owns tuple lookup, listener children, connection allocation, clocks and packet submission. The IPv4 socket module owns the shared bounded pool, port binding and file-description attachment. Each TCP connection is constructed in heap storage; no large endpoint temporary is placed on the kernel stack. A blocked call retains the existing file description through the common I/O request mechanism. Transmission advances sequence/timer state only after the IPv4 queue owns the complete encoded packet.

Supported calls include default/IPPROTO_TCP stream creation with nonblocking and close-on-exec flags, bind, listen, accept/accept4, connect, getsockname/getpeername, read/write/readv/writev, send/recv/sendmsg/recvmsg, peek/MSG_WAITALL, shutdown and poll/epoll readiness. The tested subset includes explicit loopback and wildcard bindings, TCP/UDP port separation, accepted descriptor flags, refusal/SO_ERROR clearing, vector reads crossing the 4096-byte copy buffer, retained dup descriptions and EOF/EPOLLRDHUP. TCP receives ignore source-address output and return zero address length, as native Linux does. Unsupported message flags and additional contracts remain documented below.

TCP_NODELAY and TCP_USER_TIMEOUT can be set/read; both default to zero. SO_RCVTIMEO/SO_SNDTIMEO use the common finite socket deadline mechanism. TCP_MAXSEG accepts zero or 88 through 32767 before connection; this implementation caps the effective value at 1460 and currently reports its configured limit rather than Linux's negotiated value. Post-connect TCP_MAXSEG and additional TCP options remain unsupported. Socket buffers have fixed bounded storage rather than Linux autotuning.

Initial sequences use a 32-byte secret obtained only from the ready kernel random source, a domain-separated HMAC-BLAKE2s of the IPv4/port tuple and a monotonic sequence clock. Allocation/output retries do not substitute a predictable fallback. The derivation has independent standard HMAC fixtures. This integration does not establish the full entropy, saved-state, adversarial ISN or SMP acceptance in #10/#109.

The shared Internet pool contains at most 256 sockets, with at most 32 unaccepted children per listener and 32 KiB send/receive storage per connection. After pending output has been copied, detached TIME-WAIT endpoints move to a separate 1024-record table and release their application buffers and general socket slots. Each record is at most 64 bytes, including its completed sequence state, tuple, binding, TTL and deadline. Expiry releases only elapsed records; duplicate FINs restart the 120-second timer. Completed tuples remain protected against premature reconnect and still own conflicting bound ports. Ephemeral allocation includes both live sockets and compact owners. If the table fills, the adapter keeps the original endpoint until safe reclamation; it never evicts live sequence state. Full table pressure, adapter expiry/reuse and listener pressure remain in #121.

MSG_WAITALL retains imported vector metadata and a cursor through the original file description. Delayed chunks append to the remaining user buffers; peek advances a saved offset without consuming bytes. Nonblocking calls return an available prefix, and EOF, a finite deadline or a caught signal returns already transferred bytes. Partial progress prevents SA_RESTART from replaying that prefix. An unavailable peek offset waits for more bytes rather than appearing as EOF.

## Packet and connection contract

`wire.hpp` decodes checksum-validated IPv4 TCP segments into borrowed payload views. It checks header bounds and option lengths, reads SYN MSS/window-scale options, skips unknown options and preserves the output object on malformed input. The encoder emits a minimal header and optional SYN MSS, with the IPv4 pseudo-header checksum. It supports overlapping input/output buffers. Window scaling is not offered, so peers retain unscaled 16-bit windows. Neither SACK nor timestamps are negotiated.

`connection.hpp` owns one endpoint's sequence space, application bytes, retransmission state and receive reassembly. The adapter must select a tuple, supply checksum-validated segments and a monotonic millisecond clock, and own the connection for its entire lifetime. It supplies the local MSS from the route MTU; the current upper bound is 1460. Peer MSS limits output, with a 536-byte default when no MSS option arrives. Ports and IPv4 addresses belong to the adapter.

The endpoint implements active/passive and simultaneous handshakes; established, half-close and simultaneous-close states; LAST-ACK; and 120-second TIME-WAIT. An exact-sequence reset aborts a synchronized connection, an in-window reset requests a challenge ACK, and an out-of-window reset is ignored. Future ACKs cannot release queued bytes. Old ACKs cannot update the sender window. Duplicate, overlapping and out-of-order receive bytes use bounded reassembly, with the first arrival owning overlapping bytes. A queued FIN waits for preceding data; bytes after accepted EOF are not delivered.

Each connection contains 32 KiB send storage, 32 KiB receive storage, a receive bitmap and a packet scratch buffer. Writes accept only available queue space. Limits can shrink without discarding already readable data. Peek reads preserve ownership. Reading reopens the advertised window. Read shutdown discards readable bytes while continuing to acknowledge the stream. Write shutdown sends FIN after preceding queued bytes have been transmitted.

`next()` produces a borrowed packet candidate. The adapter must copy it into an owned IPv4 output queue and then call `emitted()` immediately. A failed enqueue consumes no sequence numbers and starts no retransmission timer. Input, reads and writes invalidate the candidate. Listener/backlog ownership, tuple lookup, port allocation, file descriptions, syscall blocking, readiness and ICMP delivery belong to the kernel adapter; full fault/lifetime acceptance remains in #109/#121.

## Sending and timers

`sender.hpp` supplies RTT/RTO and byte-based Reno congestion policies. The RTO starts at one second, filters ambiguous retransmission samples, updates RTT variation before the smoothed RTT, uses the kernel's 10 ms clock granularity and clamps to one through 60 seconds. Timer loss backs off exponentially and retransmits the oldest unacknowledged data. Repeated timer loss of that same sequence range holds the slow-start threshold. Fast retransmission has its own trigger and does not consume RTO backoff.

New data respects the peer window and congestion window. Three qualifying duplicate ACKs request fast retransmission. Slow start, byte-counted congestion avoidance, recovery and timer-loss restart follow the sender policy. SYN retransmission reduces the initial data window and retains the conservative data RTO. Default Nagle coalesces small writes while earlier data remains unacknowledged; the adapter can enable TCP_NODELAY. A 200 ms sender override bounds waiting on a small advertised window. Ring wrap uses packet scratch storage to preserve full segment sizing.

Zero-window probes run independently of RTO loss, with bounded one-through-60-second backoff. Probes can request reopening with queued data or FIN and do not consume a retransmission-failure budget. Window reopening schedules outstanding data promptly. The caller can set a finite user timeout for stalled queued data or FIN; zero disables that timeout. Handshakes expire after 60 seconds. Detaching an endpoint with unread data requests a reset; detached FIN-WAIT-2 expires after 60 seconds. TIME-WAIT retains completed sequence state until its timer expires. The adapter must bound endpoint counts and reclaim storage after completion.

## Verification

Run `make test-tcp-wire test-tcp-sender test-tcp-connection test-tcp-isn test-tcp-time-wait`. All five use ASAN/UBSAN and leak checking against the production modules.

- The wire test checks independent fixed packet/checksum fixtures, every single-bit corruption of a fixture, malformed headers/options, overlapping output, sequence wrap, window/reset decisions and 50,000 checksum-repaired mutations.
- The sender test checks RTT update order, Karn filtering, SYN fallback, repeated RTOs, congestion growth/recovery and arithmetic bounds across 50,000 events.
- The connection test checks output enqueue failure, handshake/refusal/simultaneous open, overlap/gaps/queued FIN, stale/future ACK behavior, reset validation, fast retransmission/RTO, Nagle/SWS timing, finite deadlines, zero-window reopening, shutdown and close ownership. Its deterministic 300,000-byte transfer crosses the production codec while losing, duplicating and reordering packets and wrapping sequence numbers. Queue bounds and exact received bytes are checked throughout.

- The compact completed-state test checks duplicate FINs, exact/in-window/out-of-window resets, old/future ACKs, sequence wrap, zero windows, malformed input and expiry/saturating timer bounds.

`make test-tcp-native` runs the common socket/loopback program with native glibc, static musl and dynamic musl. It checks delayed/peek/nonblocking MSG_WAITALL, partial signal and deadline results, retained vector reads through concurrent close/reuse and dup2 replacement, and 300 successful half-close cycles. The retained-read cases wait until the prefix has actually been consumed before replacing the descriptor; unrelated replacement bytes and changed vector metadata must remain untouched. Peer EOF checks verify final owner release. `make test-tcp-sockets` runs both musl builds in actual BIOS/UEFI loopback guests. `make test-tcp-native-wire` runs all eight linkage/firmware/virtio transport combinations with virtio-net and e1000 together. Native Linux sockets act as both client and server through QEMU's isolated user-network bridge. Every direction transfers 262144 independently generated bytes; each guest transfers one MiB per NIC. Native endpoints check exact bytes and EOF, while the independent capture parser validates headers/checksums, MSS limits, sequence ownership, all bytes and acknowledged FINs. This bridge coverage does not replace controlled fault peers.

The user-network bridge can emit incoming resets in response to later window-update ACKs after complete close. Capture acceptance permits only exact resets after both FINs are already acknowledged and reports their count. Outgoing resets, resets during a transfer, wrong data and premature EOF still fail. `python3 scripts/tests/tcp_capture_test.py` rechecks all 16 actual NIC captures and deliberately damages six real fixtures: checksum corruption, checksum-repaired wrong bytes, malformed MSS, premature FIN, an early reset and truncation. Every damaged fixture must fail for its intended reason.

CI retains the host log in `tcp-policy`, native/guest JSON results and full PCAPs in `axiom64-evidence-tcp`, and the boot images in `axiom64-tcp-fixtures`. The corresponding source bundle includes the modules, tests, recipes and this document. Every earlier native and VM gate remains enabled. The full #109 release still requires the remaining connect/accept/send and receive lifetime contracts, broader reclamation/pressure cycles and actual controlled NIC reliability/fault evidence in #121.

## Sources and remaining work

The wire/state contract follows [RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html), retransmission timing follows [RFC 6298](https://www.rfc-editor.org/rfc/rfc6298.html), and sender congestion control follows [RFC 5681](https://www.rfc-editor.org/rfc/rfc5681.html). Linux behavior is checked against [`net/ipv4/tcp_input.c`](https://github.com/torvalds/linux/blob/3857c2fe5449541e24afc5efdb0f81a8a8f9a3a0/net/ipv4/tcp_input.c), [`tcp_output.c`](https://github.com/torvalds/linux/blob/3857c2fe5449541e24afc5efdb0f81a8a8f9a3a0/net/ipv4/tcp_output.c), [`tcp_timer.c`](https://github.com/torvalds/linux/blob/3857c2fe5449541e24afc5efdb0f81a8a8f9a3a0/net/ipv4/tcp_timer.c) and [`tcp_minisocks.c`](https://github.com/torvalds/linux/blob/3857c2fe5449541e24afc5efdb0f81a8a8f9a3a0/net/ipv4/tcp_minisocks.c), plus the socket implementation at that pinned revision. The compact close policy preserves this engine's conservative completed-state behavior; this subset does not establish every Linux TIME-WAIT reuse policy.

Additional message/address/reconnect/option behavior, ICMP/MTU error integration and complete Linux TCP options remain required, along with #121's controlled NIC and lifetime tests. IPv6 transport, urgent/OOB handling, DNS TCP fallback, TLS, full entropy/ISN acceptance and SMP are separate outstanding work. The VM operating system and required workloads come first; HP-specific development follows the readiness review in [#74](https://github.com/frankischilling/Axiom64/issues/74), after most roadmap issues and all prerequisite issues have closed with evidence. Physical boot tests and installation readiness follow the required HP driver work.
