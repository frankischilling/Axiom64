# TCP user-timeout socket and NIC acceptance

[Issue #147](https://github.com/frankischilling/Axiom64/issues/147) adds real socket and packet evidence for the configured deadline requirement in #121/#109. A receiver closes its advertised window after two clean 536-byte segments, leaving 976 of the application's 2048 bytes queued. It keeps answering actual probes with the same cumulative ACK and zero window.

The same C program runs with glibc, static musl and dynamic musl on Linux, then with both musl linkages in the VM. It checks the default option, rejects a negative value, round-trips a 2500 ms value and verifies listener inheritance. Active sockets consume ETIMEDOUT through blocking receive; passive sockets wait for POLLERR and consume it through SO_ERROR. Both then check cleared SO_ERROR, EOF, EPIPE and descriptor closure. The ten-second I/O timeout is separate and must not account for the earlier ETIMEDOUT result.

Separate active/passive control sockets leave TCP_USER_TIMEOUT at zero. Their receiver stays closed for four actual seconds, longer than the configured deadline, before reopening to 8192 bytes. Every remaining byte must arrive intact, with the recovery response and both FINs acknowledged. Each adapter carries four flows: configured active/passive and disabled-timeout active/passive. This checks short continued zero-window survival; it does not claim the full default retransmission lifetime has been accepted.

`make test-tcp-timeout-native` uses separate private Linux network namespaces and actual zero-drop AF_PACKET monitoring. `make test-tcp-timeout` covers static/dynamic guests, BIOS/UEFI and modern/legacy virtio transports, with e1000 in every VM. The earlier loss, receive-ordering and persist targets retain their original C program and default profile. All 34 full CI gates remain required.

`python3 scripts/tcp_timeout_capture.py` independently checks 22 captures and 88 flows. The packet decoder validates IPv4/TCP lengths, checksums, options and tuples. Capture and peer records must contain the same packets. Both clocks must prove the closed window, clean payload, non-progress answers, actual empty/native or one-byte/guest probes, bounded backoff and exact control recovery. Complete application log records must match the option, error consumption and elapsed-time results.

Linux's probe-only configured deadline is measured from its first persist probe; the guest's current policy measures it from the last accepted progress. The observed application error must follow the respective anchor by 2300..3300 ms, with the full stalled period bounded by 2300..4500 ms. Native comparisons typically return after about 2.7 seconds, while the guest returns after about 2.5 seconds. The verifier does not rescale clocks or require fictitious identical timestamps. Kernel receipt timestamps use system time; disagreement with independent monotonic observations invalidates the evidence.

The rejection suite changes packets and their corresponding peer records together, repairing checksums and retaining a valid packet multiset. Fourteen classes omit a probe, its answer or reopening; replace the closed window, advance an ACK or corrupt a probe sequence; alter recovered payload, the option or the returned error; falsify early/late application deadlines or reopening; shift a capture timestamp independently; or flatten control backoff. All 308 cases must fail the timeout verifier.

The socket contract follows the [Linux TCP_USER_TIMEOUT documentation](https://github.com/mkerrisk/man-pages/blob/master/man7/tcp.7), with timer behavior compared against [Linux's probe timer](https://github.com/torvalds/linux/blob/3857c2fe5449541e24afc5efdb0f81a8a8f9a3a0/net/ipv4/tcp_timer.c) and zero-window operation against [RFC 9293 section 3.8.6.1](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.8.6.1). This work leaves default retransmission lifetimes, hostile segments, broader congestion limits and route/device/MTU/ICMP requirements open. HP work follows full VM workload and driver acceptance, most roadmap issue completion and closure of every required prerequisite.
