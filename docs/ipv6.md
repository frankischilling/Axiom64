# IPv6 development

IPv6 is required by the [networking roadmap](feature-roadmap.md). The kernel has an initial Ethernet host path with explicit netlink address/route control, duplicate-address detection, neighbor discovery and unicast echo replies. An initial `AF_INET6` raw ICMPv6 and UDP implementation is under validation. IPv6 TCP, complete socket compatibility, automatic configuration and complete IPv6 acceptance remain unfinished.

`kernel/net/ipv6/wire.cpp` decodes the fixed header and bounded extension chain into a borrowed payload view. It separates complete upper-layer payloads, actual fragments, No Next Header, silent discards and parameter-problem diagnostics. Hop-by-Hop placement and unknown-option action bits follow [RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html). Unsupported routing types, including deprecated type zero, follow the unknown-type rule in [RFC 5095](https://www.rfc-editor.org/rfc/rfc5095.html). Atomic fragments bypass shared fragment state, as required by [RFC 6946](https://www.rfc-editor.org/rfc/rfc6946.html). AH and ESP remain opaque. Jumbograms and nested Fragment headers are unsupported.

The codec also encodes fixed headers, compares address prefixes and computes upper-layer pseudo-header checksums. The Ethernet receiver checks destination ownership, scoped link-local addresses, multicast membership and ICMPv6 checksums. Bounded reassembly and selected diagnostic responses are described below. Authentication and complete [ICMPv6 error suppression](https://www.rfc-editor.org/rfc/rfc4443.html) remain required. A decoded parameter problem describes an error; the Ethernet receive path decides whether to transmit a response.

Run `make test-ipv6-wire` to check an independently checksummed ICMPv6 echo fixture, padding and length boundaries, all four unknown-option actions, extension placement, routing errors, fragment boundaries and 20,000 bounded malformed inputs under address and undefined-behavior sanitizers. The existing host policy job runs this target, including the production Ethernet, address/route, neighbor and netlink modules. Unicast solicitations without a source link-layer option resolve the neighbor directly on the receiving interface before their advertisement is sent, including /128 addresses without a return route. Replies to unicast solicitations omit the target link-layer option and clear the override flag, matching the native comparison. Guest validation uses `make test-ipv6-host` for static/dynamic, BIOS/UEFI and modern/legacy profiles, with both Ethernet adapters in each boot. `sudo -n make test-ipv6-host-native` runs the same control client through three native Linux linkages on isolated TAP links. Native fixtures disable automatic link-local generation, enhanced DAD nonce options and automatic flow labels so their explicit addresses and packet fields match this cohort. They retain the normal DAD observation interval. An explicit Ethernet readiness exchange precedes address assignment. The capture auditor retains firmware packets before that boundary separately and requires all eleven kernel packets and fifteen peer inputs after it. Native MLD reports are checked and counted separately; multicast reporting in Axiom64 remains unfinished.

Physical interfaces support sixteen explicit addresses and sixteen explicit main-table routes, plus sixteen independently retained connected-prefix records. Address configuration uses permanent lifetimes, optional `IFA_F_NODAD` and `IFA_F_NOPREFIXROUTE`, and reports tentative/failed DAD state. A tentative address sends one probe and waits one complete second after device acceptance; a conflict keeps the address unusable. Failed queue attempts cannot advance DAD. Prefix routes appear while DAD is pending and remain after a permanent address fails DAD. A `NOPREFIXROUTE` address creates no route, but can preserve an existing prefix when another owner is removed; removing that companion also leaves the managed prefix for explicit route cleanup. Filling the prefix inventory makes an address addition that needs another prefix fail with `ENOBUFS` without changing its address inventory. Deleting the last ordinary address removes one matching direct prefix route in metric order, including a manual route with another protocol. Wildcard route deletion also chooses the lowest matching metric across explicit and connected routes. Other matching routes remain until a later cleanup. Automatic link-local address creation and normal manager integration remain required.

Neighbor discovery accepts all-nodes and configured solicited-node groups, rejects invalid options/checksums/hop limits and [fragmented ND messages](https://www.rfc-editor.org/rfc/rfc6980.html), and distinguishes solicitation learning from advertisement updates. The cache holds 64 neighbors. Pending resolution permits three probes one second apart; stale entries use a five-second delay before unicast probing. Reachable entries currently use a fixed thirty-second interval. Complete reachability randomization and upper-layer confirmation remain required. Kernel output owns copied bytes in a bounded 32-frame, 262144-byte queue and retires undelivered copies after four seconds. Route/source/MTU checks precede device submission.

The remaining socket work must preserve Linux `sockaddr_in6` sizes and scope identifiers, shared descriptor lifetime, retained I/O and datagram boundaries. Raw ICMPv6 receives expose the upper-layer message; the kernel calculates its transmit checksum, as described by [RFC 3542](https://www.rfc-editor.org/rfc/rfc3542.html). UDP requires the IPv6 pseudo-header checksum. Complete transport socket integration and native/guest acceptance for these interfaces remain required.

The complete feature still requires IPv6 socket/control equivalence, complete source selection and neighbor behavior, automatic configuration, multicast reporting and general membership, complete ICMPv6 errors and fragmented transport acceptance, outgoing extension controls, complete path-MTU handling, router advertisements and finite address lifetimes. Complete Linux IPv6 socket/control interfaces, UDP/TCP integration and native/guest wire coverage remain required. BIOS/UEFI, both adapters and applicable linkage/device variants must retain their existing coverage.

## Socket integration

`kernel/net/ipv6/socket.cpp` owns bounded IPv6 datagram descriptions, raw ICMPv6 filtering, UDP demultiplexing and copied receive queues. Its syscall implementation is under `kernel/net/ipv6/socket/`. The shared retained-I/O module captures `sockaddr_in6`, vectors and owned output bytes. Final close detaches asynchronous callbacks without discarding already queued packets or touching a reused socket slot. Readiness, receive/send deadlines, descriptor metadata and interface controls use the same description lifetime.

`make test-ipv6-sockets` selects the raw/UDP cohort in the existing IPv6 matrix; `sudo -n make test-ipv6-sockets-native` runs all three native linkages. The same C client exercises loopback UDP, aliases, receive copy faults, a full 20 ms receive deadline, raw creation permission and unbound-port errors. 328 argument and ownership cases cover signed lengths, full declared address imports, message address clamping, named raw protocols, scoped connect conflicts and receive-address failures after data delivery. Positive boundaries retain 24-byte and 128-byte addresses, ignore incomplete scope fields, preserve bind scope precedence and accept raw protocol zero or ICMPv6. Named AF_UNSPEC UDP output accepts a complete two-byte family and uses the connected peer; raw output uses its supplied destination. Disconnect clears the device binding. Short raw ICMPv6 output needs two protocol bytes before route lookup; zero or one byte reports `EFAULT`. Destination validation precedes that check. A fault while importing those two bytes precedes routing. Route errors precede copying the remaining payload; a later copy fault precedes the missing checksum field for two- or three-byte messages. SO_ERROR validates the input capacity before consuming the pending error, including when the later output copy faults. Each Ethernet adapter adds an application raw echo message, zero-length and vectored UDP, quoted port errors and scoped link-local UDP. Original captures require seven kernel packets and eleven peer inputs per adapter, including four malformed checksum/length inputs. Independent checks retain 32 damaged controls per native capture and 35 per guest capture. The reader requires every ABI case result and rejects foreign, short or excessive firmware traffic before readiness. Current source and complete runtime acceptance must be verified before treating this as an accepted cohort.

The socket implementation handles quoted raw/UDP errors and learned path limits as described below. A bounded global budget permits sixteen UDP port-unreachable responses per second; complete per-route error policy remains required. Source output under validation is described below. IPv4-mapped and dual-stack delivery, IPv6 TCP, complete fragmented transport acceptance, complete PMTU and quoted-error equivalence, ancillary packet information, multicast socket membership, further socket options and full Linux socket equivalence remain required. Unsupported options fail explicitly. The bounded socket inventory holds 256 descriptions and each description permits 32 queued datagrams within its receive-byte limit.

## Fragment input

`kernel/net/ipv6/reassembly.cpp` owns up to 32 copied fragment queues. Source, destination and identification select a datagram; link-local and multicast destinations also retain the receiving interface. The offset-zero fragment supplies the saved extension prefix and next-header field. Reassembly removes the Fragment header, repairs the payload length and preserves congestion marking. Exact duplicate pieces can remain harmless; partial overlaps, conflicting bytes and inconsistent final bounds discard the queue. Atomic fragments bypass matching queues, following [RFC 6946](https://www.rfc-editor.org/rfc/rfc6946.html). Reassembled packets retain their fragmented origin so neighbor discovery still rejects them.

The first-arriving fragment starts a fixed 60-second lifetime, as specified by [RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html#section-4.5). Later fragments and duplicates cannot renew it. Expiry can quote an original offset-zero fragment in a Time Exceeded response. Incomplete first-fragment transport headers produce a Parameter Problem response, subject to the existing output budget and ICMP error suppression. Malformed nonfirst fragments can also produce that diagnostic: later-fragment bytes cannot identify an ICMP error header. Address removal and network shutdown release affected fragment state. Complete fragmented transports, error policy and path-MTU behavior remain required.

`make test-ipv6-reassembly` checks reorderings, prefix ownership, overlaps, maximum payloads, scoped identities, congestion combinations, allocation failures and expiry boundaries under address and undefined-behavior sanitizers. `make test-ipv6-wire` also drives the production Ethernet/socket paths, including reassembled UDP, fragmented neighbor rejection and exact timeout quotes. Undefined-behavior diagnostics fail these targets. These host policy checks use explicit tick inputs for lifetime boundaries. The separate wire cohorts below establish the observed native and guest timing.

The separate `make test-ipv6-fragments` and `make test-ipv6-fragments-native` cohorts cover three native linkages and eight BIOS/UEFI static/dynamic modern/legacy guest profiles, each with both adapters. They exercise real raw and UDP receivers, a 65,527-byte UDP payload, varying extension prefixes, exact duplicates, overlaps, atomic-fragment isolation, scoped identities and malformed first headers. Each interface retains a real 60-second fragment context, a duplicate at 30 seconds and staggered suppression contexts. Both interfaces age concurrently through at least 70 seconds of observation, followed by late-tail and identification-reuse checks. An independent reader checks original packet bytes, diagnostics, quotes, timing and application results, and rejects damaged evidence. Native captures retain their original kernel timestamps and independent monotonic receipts, with zero dropped packets. No fragment lifetime or guest clock is shortened. The existing host and socket cohorts retain their original timing and coverage.

## Source output

`kernel/net/ipv6/output.cpp` owns copied logical datagrams, their device progress and completion. The 32-entry queue bounds retained packets and reusable fragment buffers to 262,144 bytes. `kernel/net/ipv6/fragmentation.cpp` encodes fixed-header source packets according to [RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html#section-4.5). A datagram keeps one nonzero identification from the initialized random generator. At most eight pieces per datagram are submitted in each poll. Only device acceptance advances the offset; a later MTU increase keeps a partially transmitted datagram fragmented. Route, source ownership and MTU are checked again after device polling. Cancellation defers release of a borrowed buffer until submission returns. Closing a socket retains already queued packets and detaches callbacks from a reused description.

Raw ICMPv6 can send up to 65,535 upper-layer bytes; UDP can send up to 65,527 application bytes. `IPV6_MTU_DISCOVER` defaults to `WANT`. `DONT`, `WANT` and `OMIT` permit local fragmentation; `DO`, `PROBE` and `INTERFACE` reject sends above the selected MTU. `DONT`, `WANT` and `DO` use learned path limits; `PROBE`, `INTERFACE` and `OMIT` use the interface MTU for output. `IPV6_DONTFRAG` forbids splitting independently. `IPV6_MTU` accepts zero to clear the socket setting, or a value of at least 1,280. It limits pieces when fragmentation is needed and the admission size when splitting is forbidden. A permitted unfragmented packet can still use the selected path limit. The getter reads the description's retained destination, including a learned exception even when the send policy bypasses it. Raw sends select a fresh output route without replacing that query view. Connected unnamed UDP output refreshes it; device binding and disconnect clear it, while reconnect creates a new view. Retained metrics survive output-cache expiry or eviction, share further reductions, and remain owned until the last description releases them. Send quotas currently count logical datagram bytes; exact Linux send-memory accounting remains unfinished.

`make test-ipv6-fragmentation` checks 54 datagrams and 452 encoded pieces, maximum lengths, MTU transitions and rejected bounds under sanitizers. The production host tests also cover copied data, both adapters, partial device acceptance, queue pressure, allocation failure, random readiness, MTU and address changes during polling, close/reuse and network shutdown. These policy tests do not establish guest wire acceptance.

`make test-ipv6-output` and `make test-ipv6-output-native` run a shared C client through three native linkages and eight guest profiles. It checks 432 sends and 42 option/fault cases across both adapters, raw/UDP sockets, global/link-local scope and nine policy configurations. Original captures must establish complete reassembly, every application byte and checksum, copied vectors and descriptor retirement. Rejected sends retain a real fifty-millisecond observation. The independent reader rejects twelve damaged controls per capture. Host, socket and fragment cohorts remain required alongside output checks. Native captures require stable original kernel/monotonic clocks and zero drops. The source encoder currently accepts fixed-header transport packets; complete outgoing extension-header controls remain required.

## Learned path MTU and quoted errors

`kernel/net/ipv6/icmp.cpp` walks bounded quoted extension headers without requiring the quoted packet's entire payload. It requires the first eight transport bytes and ignores nonfirst fragments. The enclosing IPv6 receive path validates the actual ICMPv6 checksum before an error can affect a description. Raw and UDP matching uses the quoted local/remote addresses and device binding; UDP also matches both ports and selects one description. Hard Destination Unreachable and Parameter Problem errors replace the description's pending error. With `IPV6_RECVERR` disabled, soft unreachable and Time Exceeded messages do not become ordinary connected-socket errors. `SO_ERROR` consumes the pending error once.

The 64-entry path cache owns source, destination, next hop, interface and route identity. A valid Packet Too Big report can reduce a selected path to at least 1,280 bytes. Equal, increasing and sub-minimum reports do not renew the exception. The first lower report starts a ten-minute lifetime; further reductions and ordinary reads preserve that deadline, matching the [Linux destination expiry policy](https://github.com/torvalds/linux/blob/v7.0/include/net/dst.h). Deleting a route retires its entries, while a new more-specific route has an independent identity. Removing the last source address discards its exceptions. Link MTU changes adjust affected entries without extending their original deadlines. Output checks the current learned limit again after driver polling, including when it retains a partially sent datagram.

With `IPV6_RECVERR` disabled, connected UDP reports `EMSGSIZE` for Packet Too Big under `WANT`, `DO` and `PROBE`; `DONT` learns without a pending ordinary error. UDP `INTERFACE` and `OMIT` ignore that hint. Raw ICMPv6 learns independently and reports a pending `EMSGSIZE` only under `DO`. These distinctions follow native comparisons and the [Linux v7.0 UDP](https://github.com/torvalds/linux/blob/v7.0/net/ipv6/udp.c) and [raw ICMPv6](https://github.com/torvalds/linux/blob/v7.0/net/ipv6/raw.c) error paths. A closed raw description does not erase a learned route limit. Complete error-queue and destination-cache equivalence, TCP integration, ancillary MTU notifications, outgoing extension controls and full PMTU/error acceptance remain required.

`make test-ipv6-path-mtu` checks cache ownership, capacity, eviction, exact lifetime boundaries, link changes, truncated quotes, extension headers and 20,000 malformed inputs under sanitizers. `make test-ipv6-wire` also checks the actual Ethernet/socket path through learning, fragmentation, interface probing, error replacement, route changes and source removal. It rejects mismatched quoted ports and injects a real hint during driver polling to prove that oversized bytes are withheld before copying.

`make test-ipv6-pmtu` and `sudo -n make test-ipv6-pmtu-native` cover eight guest profiles and three native linkages. The peer starts that observation only after an independent collector sees the complete injected hint. Guest captures retain the original packet timestamp and a separate monotonic receipt; native collection uses the existing packet monitor. The same client fails against a retained earlier kernel at its first learned-limit check. The existing host, socket, output and fragment cohorts remain required. Original native kernel/monotonic clocks and zero drops are mandatory. The ten-minute cache lifetime also has sanitizer boundary coverage. Complete PMTU/quoted-error acceptance remains required.

`make test-ipv6-expiry` and `sudo -n make test-ipv6-expiry-native` observe the real ten-minute lifetime on both adapters. Each execution retains 32 connected raw/UDP paths across global and link-local scope. Repeated lookups and ordinary small sends keep paths active throughout the observation. Expiry is checked through actual sends, separately from the retained destination reported by `IPV6_MTU`. ## Extended error queues

Raw ICMPv6 and UDP descriptions support `IPV6_RECVERR`. It defaults off and is shared by descriptor aliases. Accepted ICMPv6 errors retain copied quoted transport bytes, the original destination, the reporting address, error type/code and information field. UDP returns the quoted application payload; raw sockets include the ICMPv6 header. Enabling delivery also reports accepted soft errors through the ordinary pending error. UDP `INTERFACE` and `OMIT` still ignore Packet Too Big hints.

`recvmsg(MSG_ERRQUEUE)` returns the Linux x86-64 `IPV6_RECVERR` control message with a 16-byte extended error and 28-byte offender address. Local MTU rejection queues an empty `SO_EE_ORIGIN_LOCAL` record with the MTU and a zero offender. `recvfrom(MSG_ERRQUEUE)` returns the copied payload and original destination without ancillary output. The ABI follows native comparisons and the [Linux v7.0 error-queue implementation](https://github.com/torvalds/linux/blob/v7.0/net/ipv6/datagram.c).

Error receives dequeue once, including with `MSG_PEEK`, and return the copied length even with input `MSG_TRUNC`. An empty queue returns `EAGAIN` immediately on a blocking description. Invalid message/vector metadata leaves the record queued; later payload, address and result-copy faults consume it. Short control buffers report `MSG_CTRUNC`, preserve untouched padding and retain the observed Linux copy-fault ordering. Normal data and error records stay independent. `POLLERR` remains set while records remain even after `SO_ERROR` is cleared; dequeue can rearm the next pending ICMPv6 error. Disabling delivery purges records while preserving the ordinary pending error. Final close releases every owned record.

Vector imports validate signed lengths and complete address spans before dequeue. The single-vector clamp and bounded total follow [Linux v7.0 vector imports](https://github.com/torvalds/linux/blob/v7.0/lib/iov_iter.c).

Each description holds at most 32 error records within the shared logical receive-byte budget. This bounds copied metadata and payloads; exact Linux socket-memory accounting remains required. Output checks route and MTU admission before importing the remaining payload. Raw output first imports its two protocol bytes. IPv6 scalar option getters import the unsigned capacity before option lookup, clamp it to the scalar size and write its length before copying the value, following the [Linux v7.0 controls](https://github.com/torvalds/linux/blob/v7.0/net/ipv6/ipv6_sockglue.c).

`make test-ipv6-errors` covers all eight guest profiles; `sudo -n make test-ipv6-errors-native` runs three native linkages. The same client checks 30 receive-copy cases, eight wide-vector groups, 96 length/pointer admission cases, 26 option groups, four shared-description/data-queue lifetimes and 120 wire cases across both adapters. Independent readers compare every copied destination, control and payload byte with the original quoted traffic and reject fourteen damaged controls per capture. Local error-queue runs pass these three native and eight guest profiles. Complete current-source native timing acceptance remains required: captures with unstable kernel/monotonic clock binding stay rejected.

`make test-ipv6-fragment-observation` reproduces delayed first-fragment release in the real peer scheduler. Suppression inputs, the thirty-second duplicate and the full seventy-one-second peer observation start from that release. Actual wire checks retain the original sixty-second reassembly lifetime, staggered suppression spacing and at least seventy seconds of captured observation. No guest clock or packet timestamp is rescaled. Complete Linux IPv6 error/option equivalence and the remaining feature scope above stay required.
