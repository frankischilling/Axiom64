# Controlled TCP loss acceptance

[Issue #135](https://github.com/frankischilling/Axiom64/issues/135) covers the first integrated loss subset of [#121](https://github.com/frankischilling/Axiom64/issues/121) and [#109](https://github.com/frankischilling/Axiom64/issues/109). A separate Ethernet/TCP endpoint deliberately discards the first guest SYN or SYN-ACK, first data segment and first FIN on each active/passive stream. It acknowledges only the actual retransmitted sequence ranges. The guest's ordinary Linux socket calls deliver 65536 exact bytes in each direction and verify half-close and EOF.

The peer advertises MSS/window 536 for the initial data segment, then permits a larger bounded window. Handshake loss must produce an elapsed retransmission near one second; the first data retry must wait for the three-second reset required by [RFC 6298 section 5.7](https://www.rfc-editor.org/rfc/rfc6298.html#section-5.7). Later FIN retry timing is recorded separately: the current guest has a one-second RTO floor, while native Linux can retransmit sooner. These observations establish this sequence, rather than complete congestion, backoff or deadline acceptance. Peer sequence space begins at `0xfffffff0` and both exact streams and final FIN acknowledgments are checked across its wrap.

`make test-tcp-fault-native` runs the same C program with glibc, static musl and dynamic musl. It requires root for nested private network namespaces and veth devices; host interfaces and routes are outside those namespaces. Checksums and segmentation offload are disabled on the private links so an independent AF_PACKET monitor records complete on-wire bytes. A wrapper reports the actual client's exit status and retains its namespace until both endpoint and capture sockets have finished draining. Only then are the private links released; a capture error remains a failed case.

`make test-tcp-fault` builds one static and one dynamic image, then exercises both firmware modes and both virtio transports. Every VM includes virtio-net and e1000, with active and passive opens on each. QEMU records both adapters independently of the endpoint. `python3 scripts/tcp_fault_capture.py` verifies every actual frame, checksum, payload byte, dropped/retransmitted range, elapsed timer, wrapped peer sequence and final FIN acknowledgment. `python3 scripts/tests/tcp_fault_capture_test.py` rejects seven damage classes per capture, including a changed payload with repaired checksum and falsified retry timestamps. The complete matrix supplies 32 guest streams and 12 native streams, 22 captures and 154 rejection cases.

The dedicated `tcp-fault` CI job adds this evidence without replacing any earlier build, native, loopback, ordinary NIC or networking suite. Logs, independent peer records, captures, verified results, both boot fixtures and exact corresponding sources/inputs are published. Wider hostile-segment, reordering/overlap, zero-window/persist, default/configured deadline, queue/device/route/ICMP/MTU and reclamation requirements remain open in #121/#109. Full TCP, VM daily-testing and HP readiness remain unproven; VM prerequisites precede HP-specific work.

Each native capture socket reserves its own four-MiB receive budget with Linux `SO_RCVBUFFORCE`; this does not change a host sysctl. `PACKET_STATISTICS` must report zero kernel receive drops before the namespace is released. The native target first checks a 1000-frame burst while the actual capture writer is held, proving exact collection, then deliberately shrinks the socket budget and requires the kernel's reported overflow to fail. The capture verifier treats the native and VM result files as read-only inputs. It writes `tcp-fault-capture-results.json` separately, including each input report's hash; this permits ordinary CI verification of the privileged native test's immutable evidence.

The additional [receive-ordering profile](tcp-reordering.md) reuses this application's loss and exact-stream requirements while adding real receive holes, duplicates and consistently valued overlaps. Its evidence has separate names; the default loss profile and its complete matrix remain required.
