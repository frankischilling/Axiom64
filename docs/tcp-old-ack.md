# TCP old-ACK validation

An ACK below the validated send-history bound must be rejected before its segment can update a peer window, deliver data, consume FIN or reset a progress deadline. The production connection limits the learned maximum peer window by acknowledged sequence history and retains the upper bound at `SND.NXT`. Equality at the lower bound and ordinary duplicate ACKs remain acceptable. Current peer windows are unscaled 16-bit values; acknowledged history therefore saturates at 65535 instead of becoming ambiguous after a full sequence-number wrap. SYN and FIN acknowledgments count as sequence history.

This follows the rejection and reply rule in [RFC 5961 section 5.2](https://www.rfc-editor.org/rfc/rfc5961.html#section-5.2), the processing order in [RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.10.7.4), and the history-limited window in [the pinned Linux ACK implementation](https://github.com/torvalds/linux/blob/3857c2fe5449541e24afc5efdb0f81a8a8f9a3a0/net/ipv4/tcp_input.c). The sanitizer regression uses the production encoder/checksum/decoder for 73 boundary, short-history, window-growth, wrap, payload, FIN, exact-recovery and unchanged-deadline cases. Local native comparisons use Linux `6.6.87.2-microsoft-standard-WSL2`; [the source for that version](https://github.com/microsoft/WSL2-Linux-Kernel/blob/427645e3db3a8896714f22a3d3fe0c3f7b317ad4/net/ipv4/tcp_input.c) also limits the learned window by acknowledged history. Hosted comparisons use the runner's installed kernel. The packet profile deliberately exercises acknowledged history exceeding the learned window. Short-history policy is checked against the pinned sources and production regression rather than inferred from those long-stream packets.

`test-tcp-old-ack-native` runs the unchanged socket client with glibc, static musl and dynamic musl in separate peer/client network namespaces. `test-tcp-old-ack` runs both musl clients in BIOS/UEFI and modern/legacy virtio modes, with virtio-net and e1000 active together. Each of the four active/accepted flows retains actual SYN/data/FIN loss, original elapsed retries, peer sequence wrap and 65536 exact bytes in each direction.

After the guest FIN is acknowledged, an independent peer sends three in-window segments: poisoned data, FIN, then poisoned data plus FIN. Each ACK is exactly one byte below `SND.UNA - 8192`, while advertising a forged 65535-byte window. Each actual challenge ACK must preserve `RCV.NXT`; subsequent injections wait 1200 real milliseconds after the previous response. The original reply starts only after all three rejection barriers, then completes every byte and valid FIN. Learning the forged window before rejection makes a later attack acceptable and fails this test. The vulnerable baseline delivers poisoned bytes and fails the unchanged socket client.

`scripts/tcp_old_ack_capture.py` independently checks all 22 captures, 44 flows and 132 injection/response barriers, using every actual frame from the peer and PCAP records. Only independently proven rejected injections are excluded from the original reply-stream byte check. Original loss clocks, ACK ownership, exact payload and final FIN acknowledgments remain required. Native capture-drop statistics, actual socket logs, firmware and both driver modes are checked as well.

`scripts/tests/tcp_old_ack_capture_test.py` rejects 28 synchronized damaged cases per capture, covering both active and accepted flows. Removing each injection, changing its ACK to the boundary/inside/future, moving its sequence, hiding the forged window, removing or fabricating a response, acknowledging poisoned data/FIN, or shortening both recorded waits must fail even when packet and peer frame counts agree. All 616 damaged cases must fail. Full CI retains every earlier loss, ordering, persist, user-timeout, UDP/DNS and normal-manager gate and publishes all ten TCP images plus exact inputs, products, logs and packets before integration.

This completes the old-ACK child requirement only. Challenge-ACK throttling, broader malformed/reset/SYN coverage, complete default retransmission lifetime and route/device/MTU/ICMP behavior remain in #121/#109. Complete VM workloads and all hardware prerequisites still precede HP development.
