# Network manager integration

`/sbin/network-manager` runs independent Ring 3 clients for up to eight Ethernet interfaces. Normal init starts it as a separate child alongside the desktop and console, and retries an exited manager after one second. Missing adapters and DHCP servers do not delay those other children. A missing profile defaults to DHCP; validated static and disabled profiles take precedence per interface. An unsafe profile excludes its interface rather than accepting a default. Issue [#78](https://github.com/frankischilling/Axiom64/issues/78) still requires the complete fault, protocol, startup, and fresh-boot verification matrix before this integration is complete.

The foreground manager accepts `--runtime DIR`, `--saved DIR`, `--resolver-runtime DIR`, and `--resolver-target FILE`. Defaults are `/run/network-manager`, `/etc/network`, `/run/network-resolver`, and `/etc/resolv.conf`. Runtime and saved directories are private; the resolver uses a separate public directory under traversable parents. Saved profiles follow the [configuration format](network-configuration.md#saved-profiles-and-lease-hints). Runtime state is volatile; saved profiles and address hints survive on an ext2 root. A saved address is only a hint for an INIT-REBOOT request; the new request establishes fresh monotonic deadlines.

Each pass rotates its starting interface and limits every interface to four receive operations and two actions. All descriptors are nonblocking and close-on-exec. The manager rereads monotonic time after synchronous operations and before delivering replies or completions. DHCP expiry and rebinding transitions precede delayed replies. Installation checks address/routes, the configured UDP binding, global resolver publication, and the saved hint before acknowledging the action. Failure attempts checked withdrawal of those results. An interface's failure leaves other clients running. Owned resolver contributions merge by metric; manual addresses, routes, and resolver files keep their existing ownership policy.

Static profiles run three RFC 5227 probes before installation and two announcements afterward. A pre-installation conflict blocks that saved address. After installation, the first conflict may trigger one defensive announcement; another conflict within ten seconds relinquishes ownership and blocks the profile until the configuring process restarts. Carrier changes cannot bypass a known conflict. A static client never sends DHCP or substitutes a different address.

SIGTERM and SIGINT request DHCP release and owned withdrawal. The DHCP module allows a 200 ms release window. The manager gives pending teardown two seconds of event-loop time, then attempts final checked cleanup and descriptor close; an unfinished operation produces an error exit. These scheduling budgets do not bound total wall time during synchronous disk operations. Each existing storage request can wait up to 30 seconds, and serial file/route cleanup across interfaces can extend shutdown further. Failed cleanup retains synchronized records for recovery by a later process. Configuration, routing, transport, and singleton descriptor closes report errors; descriptors are consumed even when close reports an error.

`userspace/net/manager/ownership.hpp` exposes `ax::net::Ownership`. Call `open(runtime)` before opening configuration or resolver journals. It validates the private runtime path, opens a permanent `manager.lock` file, and acquires an exclusive nonblocking open-description lock. The containing directory must belong to the effective UID with mode 0700. Its ancestors must belong to root or that UID, and writable ancestors must be sticky. The file must be regular, owned by the effective UID, mode 0600, and have one link. Symlinks, unsafe path spelling, unsupported types, and inode substitution are rejected. Newly created directories and files receive their exact modes even under restrictive umasks.

The private path policy is shared with saved profiles. Acquisition checks the opened inode against its directory entry after locking and any creation synchronization. It never truncates, renames, or unlinks the lock file, including when acquisition fails. Competing opens return `EWOULDBLOCK`/`EAGAIN`; reopening an already held object returns `EALREADY`. Descriptors are nonblocking and close-on-exec. Explicit `close()` reports errors and is idempotent; destruction performs best-effort close. Final descriptor close or process death releases ownership while preserving the inode for the next process. The class cannot be copied.

Select a runtime directory on volatile storage, such as `/run/network-manager`. The kernel mounts `/run` as RAM storage when selecting an ext2 root, so runtime ownership records do not preserve lease deadlines across reboot. Saved profiles and address hints belong on the persistent root and still require fresh lease validation. Kernel accounts and permissions remain tracked in #9; effective-UID metadata checks operate within the documented trusted writer policy. The current random-byte source is not a cryptographic generator, and a development fresh-boot fixture has observed repeating transaction IDs. Strong randomness and fresh-boot transaction verification remain required in #10/#78.

Run the manager and ownership checks with:

```sh
sudo make test-ownership-native
make test-ownership
make test-static-address
make test-manager
# Focus one firmware/transport cell; both musl linkages run by default.
python3 scripts/manager_test.py --firmware bios --transport modern
# Focus one scenario while preserving packet counters for each repetition.
python3 scripts/manager_test.py --scenario disabled --linkage static --firmware bios --transport modern --repeat 5
```

The native program runs with GNU ASAN/UBSAN and static/dynamic musl under ordinary and root UIDs. It checks eight simultaneous contenders creating the first lock, exact private modes, stable inode and opaque contents, fork/exec descriptor lifetime, restart after SIGKILL, hard links, symlinks, unsupported types, repeated writerless-FIFO rejection, and real foreign file/directory owners under root. A linker wrapper substitutes a real inode after real flock acquisition to check rejection and release. The guest matrix runs both musl programs on RAM and disposable writable ext2 across BIOS/UEFI and modern/legacy virtio. It requires clean unmount, independent host fsck, and unchanged seed bytes. Evidence is in `build/ownership-*.log`, `build/ownership-native-results.json`, and `build/ownership-results.json`. Native-only FIFO creation and foreign-owner setup are not guest credential claims.

The static-address sanitizer program exercises probe and announcement spacing, stale completion tokens, installation retry and rollback, pre-installation conflicts, defense failures, the ten-second defense boundary, carrier changes, and stop. The manager fixture boots the actual kernel with virtio-net and e1000 peers and forks/execs the foreground manager. Thirteen scenarios cover concurrent DHCP renewal/rebinding, a missing peer, static/disabled/unsafe overrides, static conflict rejection and defense/relinquishment, a manual address, SIGKILL/restart, and four publication/teardown failures. Both musl linkages run across BIOS/UEFI and modern/legacy virtio, for 104 boots. The observer independently queries address tuples, routes, resolver files, saved hints, journals, and actual child exit statuses. A second process must fail singleton acquisition before recovery. Peers validate packet fields, checksums, sources, ARP, and counts, which remain in failed reports too.

Fault-test binaries inject a directory synchronization failure after a hint's real rename, a resolver publication rename failure, persistent hint-removal failure, and a UDP descriptor close error after the real close. Surrounding operations use real files and sockets. Failed installation must withdraw its address/routes/resolver metadata and hint while the other interface progresses. Incomplete teardown must exit with an error; a normal new process then reacquires both interfaces and completes clean teardown. The normal installed manager has no fault selection. Evidence uses `build/manager-*.log` and `build/manager-*-results.json`. Full malformed/duplicate/reordered packet, NAK/expiry/infinite/invalid lease, carrier/device-fault, fresh ext2-root reboot, and normal-init supervision proofs remain required by #78.

Linux open-description semantics follow the [flock implementation](https://github.com/torvalds/linux/blob/v6.12/fs/locks.c) and [API](https://man7.org/linux/man-pages/man2/flock.2.html). The manager's protocol requirements remain [DHCP](https://www.rfc-editor.org/rfc/rfc2131) and [IPv4 address conflict detection](https://www.rfc-editor.org/rfc/rfc5227).
