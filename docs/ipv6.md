# IPv6 development

IPv6 is required by the [networking roadmap](feature-roadmap.md). The kernel has an initial Ethernet host path with explicit netlink address/route control, duplicate-address detection, neighbor discovery and unicast echo replies. An initial `AF_INET6` raw ICMPv6 and UDP implementation is under validation. IPv6 TCP, complete socket compatibility, automatic configuration and complete IPv6 acceptance remain unfinished.

Automatic link-local addressing is being integrated. Host sanitizer tests cover per-link configuration, EUI64 addresses, stable opaque identifiers, interface down/up, IPv6 disable/enable and entropy that is not ready. Generated identifiers use HMAC-BLAKE2s following RFC 7217; randomly created interface secrets last until network shutdown. Enhanced DAD uses nonce options to recognize looped solicitations. A stable privacy address can try three new identifiers after conflicts. Its retry counter belongs to that address owner. A fresh link-local initialization after IPv6 disable/enable or an administrative restart starts at the initial identifier with its full retry budget. A retired owner cannot consume attempts or defer the first probe of that fresh address. Changing the generation mode does not cancel an existing stable owner's retry. Each regenerated candidate waits a complete second plus zero-to-one-second random jitter before DAD; the tick deadline rounds upward to preserve that minimum. Missing entropy postpones transmission. An explicitly removed address does not give the generator ownership of a later manual replacement. Installing a stable secret selects privacy mode without immediately generating an address. A default secret changes existing interfaces' modes while preserving the default mode itself. Router solicitation, advertisement processing and SLAAC have local model and initial application checks; complete automatic-address wire acceptance remains unfinished.

Stable SLAAC regeneration copies the failed object's configured preferred and valid lifetimes. The independently learned on-link route keeps its original deadline. After four distinct stable trials, or one failed EUI-64 trial, a nonpermanent automatic address is removed. The last exhausted automatic owner also retires its learned prefix route. Other address objects, manual or replaced routes, and unrelated learned prefixes retain their ownership. Failed permanent addresses, including generated link-local addresses and manually promoted stable addresses, stay visible and unusable. Stable replacements preserve the original flags and raw preferred/valid lifetimes. A retained `NODAD` flag completes a regenerated candidate after its retry hold without sending another probe. Failed finite configured addresses are removed before valid expiry; a later successful address creation starts fresh DAD for a new owner unless the request retains `NODAD`. Explicit removal of the last matching address also retires its learned prefix. A new replacement is published before a failed nonpermanent owner is removed, so cleanup can see the surviving owner. Receive-path sanitizer checks cover these ownership rules, entropy and nonce backpressure, raw lifetime copying and carrier readiness.

Neighbor discovery accepts all-nodes and configured solicited-node groups, rejects invalid options/checksums/hop limits and [fragmented ND messages](https://www.rfc-editor.org/rfc/rfc6980.html), and distinguishes solicitation learning from advertisement updates. A query uses the data source when that address belongs to the outgoing interface. When the data source belongs to another interface, queries use a ready outgoing link-local address; without one, no solicitation is emitted.
