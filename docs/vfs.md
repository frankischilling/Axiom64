# Filesystems and mounts

The boot initramfs supplies the initial RAM root; [disk-root selection](disk-root.md) can replace it with ext2 before Ring 3 starts. User programs can mount independent `ramfs` volumes or [classic ext2 disks](ext2.md) on existing directories, remount them read-only or writable, and unmount them when unused.

## Kernel interface

`kernel/include/fs/vfs.hpp` defines `FilesystemOps`, `Mount`, `Node`, and `Path`. The VFS resolves paths and applies mount policy before dispatching lookup, creation, links, removal, rename, file reads/writes, truncation, metadata, enumeration, sync, and shared mapping to the filesystem. `kernel/fs/ramfs.cpp` and `kernel/fs/ext2/ext2.cpp` implement those operations. Filesystems can reject remount and perform final clean-state writes before unmount. Statistics return errors when metadata cannot be read. Initramfs import initializes the boot volume; device operations continue through their drivers.

Each node belongs to one mount. `stat.st_dev` identifies that mount; hard links share an inode within it. A path retains its starting directory node, so relative access through a working directory or directory descriptor keeps its identity when a mount covers that directory. Traversal resolves symlinks before `..`; a mounted root's `..` reaches the covered directory's parent. Names can contain 255 bytes. User paths are bounded to 1,023 bytes and symlink expansion to 2,047 bytes, with at most 40 followed links.

The ELF loader and private file mappings read through the filesystem interface. Shared mappings request backing from the filesystem and return `ENODEV` when it has no shared-mapping operation. RAM shared pages remain referenced after descriptors close and across fork. A mapping created from a read-only descriptor or mount cannot gain write access through `mprotect`.

## Guest operations

| Operation | Supported behavior |
| --- | --- |
| `mount` | `ramfs` and `ext2`, optional `MS_RDONLY`; `MS_REMOUNT` changes policy; the mount utility's `MS_SILENT` flag is accepted |
| `umount2` | Flags zero; sync before detach and restore covered contents |
| `openat`, `mkdirat`, `unlinkat`, `linkat`, `renameat`, `symlinkat`, `readlinkat` | Relative directory identity and filesystem dispatch |
| `O_PATH` descriptors | Retained object identity, metadata, duplication, directory bases and empty-path symlink reads |
| `rename` | Atomic RAM namespace update, replacement, and retained open descriptions |
| `renameat2` | Zero flags or `RENAME_NOREPLACE`; publish to an absent name without replacing files, directories, hardlinks or symlinks |
| `statfs`, `fstatfs` | Filesystem type, mount identity, name limit, read-only flag, and backend capacity/allocation information |
| `fsync`, `fdatasync`, `sync` | Filesystem sync delegation; raw block descriptors use the disk flush operation |
| `truncate`, `ftruncate` | Filesystem delegation with negative-length, file-type, capacity, and mount checks |
| `flock` | [Advisory shared/exclusive locks](file-locks.md) owned by a canonical local file description |
| `fcntl` record locks | POSIX and open-file-description byte ranges, foreign conflict queries, blocking acquisition and descriptor lifetime |
| `proc` mounts | Real process/thread status and enumeration, caller-relative self links and description-owned read buffers |

Record locking supports `F_GETLK`, `F_SETLK`, `F_SETLKW` and their OFD equivalents. Ranges normalize SEEK_SET/CUR/END, negative lengths and zero lengths extending through future growth. Own locks split, convert and coalesce. POSIX locks belong to a file table and closing an ordinary descriptor for the inode releases them; closing an `O_PATH` descriptor preserves them. OFD locks belong to an open file description and survive dup/fork until its final close. Multithreaded exec retains an exclusively owned table after sibling cleanup, preserving POSIX locks; a close-on-exec ordinary alias still releases them. These ownership rules follow [Linux's record-lock contract](https://man7.org/linux/man-pages/man2/fcntl_locking.2.html), [Linux 6.17 close behavior](https://github.com/torvalds/linux/blob/v6.17/fs/open.c), and [Linux 6.17 exec ordering](https://github.com/torvalds/linux/blob/v6.17/fs/exec.c).

The module stores at most 2,048 ranges and reports ENOLCK when an atomic replacement would exceed capacity. Invalid ranges, overflow, access modes and OFD owner fields fail explicitly. Node-less anonymous handles currently return EOPNOTSUPP. A blocked POSIX acquisition whose descriptor is replaced returns EBADF and releases the acquired process locks; an OFD acquisition retains its original description. Native and guest controls exercise two- and three-process deadlocks, interrupted and restarted waits, stop/continue, fatal exit, exec, shared-table descriptor replacement, inode aliases, unlink/replacement and atomic overflow rejection. Guest RAM/ext2 cases additionally check range exhaustion and independent reboot reads with exact host-exported seed bytes and filesystem checks. Complete Linux lock behavior across future filesystem and namespace implementations remains planned.

`O_PATH` keeps an object's identity without opening it for data or device I/O, following [Linux's path-descriptor contract](https://man7.org/linux/man-pages/man2/open.2.html). Only `O_CLOEXEC`, `O_DIRECTORY` and `O_NOFOLLOW` modify a path open; access, creation and truncation flags are ignored. Traversal still checks directory search permissions. `O_PATH|O_NOFOLLOW` retains the final symlink itself, including after namespace replacement, and `readlinkat(fd, "", ...)` reads that retained target. Metadata queries, duplication and descriptor flags work; path-directory descriptions support relative lookup, `AT_EMPTY_PATH` metadata and `fchdir`. A mounted block device can be inspected without opening it for raw I/O. Data I/O, mapping, raw metadata mutation, enumeration, locking and socket/epoll control reject the descriptor with `EBADF`. Poll reports `POLLNVAL`; select uses Linux's default ready result for this descriptor type.

A read-only mount rejects file writes and namespace or metadata mutations with `EROFS`. Read-only remount returns `EBUSY` while writable regular-file descriptions or shared file pages remain. Unmount returns `EBUSY` for open descriptions, live working directories, bound Unix sockets, shared pages, or nested mounts. Cross-filesystem links and renames return `EXDEV`. RAM files removed or replaced remain usable through existing descriptions.

`RENAME_NOREPLACE` checks the destination during the serialized namespace operation and returns `EEXIST` if it already exists, including when both names refer to the same inode. Directory destinations may have a trailing slash; a regular-file source with a trailing destination slash returns `ENOTDIR`. `RENAME_EXCHANGE` and `RENAME_WHITEOUT` return `EOPNOTSUPP`; unknown bits and conflicting flag combinations return `EINVAL`. These rules follow [Linux 6.17 rename handling](https://github.com/torvalds/linux/blob/v6.17/fs/namei.c). Ext2 storage failures retain the [documented partial-write limitations](ext2.md); namespace exclusion does not establish crash durability.

## Verification and limits

`userspace/tests/fs/vfs.c` runs from the ABI and full guest suites under both firmware types. It checks covered and restored contents, pre-existing directory descriptors, symlinks and loops, mount traversal, long names, directory enumeration, hard links, replacement and unlink lifetime, read-only operations, static/dynamic executable loading from a mounted volume, private/shared mappings, socket bindings, nested mounts, inherited working directories, and repeated mount-slot reuse. `VFS_TESTS_PASS` is mandatory. Existing ABI, native toolchain, desktop, and raw disk tests remain required.

`scripts/rename_test.py` compares six native libc/linkage profiles with 32 RAM/ext2 guest cells across both maintained musl providers, linkage types, firmware paths and block transports. Each client checks ten behavior groups and 32 concurrent publications with exactly one winner. Existing destinations retain their inode and contents. Persistent cells retain their final images and require independent filesystem checks.

`scripts/path_descriptor_test.py --native --directory build/path-descriptors-native --fixtures /tmp/axiom64-path-descriptors` compares six real Linux libc/linkage profiles. Run it as root so its child can drop all supplementary groups and switch to an ordinary identity. The fixture directory must be new and on a Linux filesystem; the results retain its exact archive and metadata. Omitting `--native` runs 32 RAM/ext2 guest cells across both maintained musl providers, linkage types, firmware paths and transports. Native and RAM clients make 71 observations; ext2 clients add four mounted-device metadata and denied-read checks. Every client retains the original 60 checks and uses real child processes to query POSIX lock conflicts after path and ordinary descriptor closure. Six checks run with an ordinary identity. Persistent guest cells retain compressed disks and require strict host filesystem checks. Source copies, compiler commands, products and execution logs accompany the results. Cancellation tests also require the actual native parent's entire process group to stop.

There are 16 mount slots including the root, and a shared pool of 16,384 RAM nodes. Unmount frees a volume's owned data and nodes. Removed nodes on an active volume remain allocated, so repeated create/unlink can exhaust that pool. RAM files have a 256 MiB limit; growth that would relocate shared backing returns `EBUSY`. RAM statistics report zero block capacity because there is no fixed block allocation pool.

The namespace is global and kernel filesystem calls are serialized on one CPU. [Credential policy](credentials.md) enforces DAC, ownership, sticky/set-ID rules, chroot and read-only/nosuid/nodev/noexec mounts. Bind mounts, stacked mounts, runtime root replacement, mount namespaces, lazy/forced unmount, extended access controls, further mount options and additional filesystem types remain in the VFS roadmap. Boot-time ext2 root selection is described in [disk-root support](disk-root.md). Private mappings eagerly copy bytes and do not retain filesystem references; general file-backed virtual-memory lifetime and writeback are still planned. Read-only remount conservatively treats all shared file pages as busy, including read-only mappings. Ext2 also rejects it while an unlinked inode is referenced.

The interface follows the concepts described in the [Linux VFS documentation](https://www.kernel.org/doc/html/latest/filesystems/vfs.html). Supported mount behavior is checked against the Linux [mount](https://man7.org/linux/man-pages/man2/mount.2.html) and [umount](https://man7.org/linux/man-pages/man2/umount.2.html) contracts; the limits above identify the current subset.
